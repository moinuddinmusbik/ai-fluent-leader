## The Big Idea

Most leaders build one AI agent — the email demo — and stop. Each new real problem (insurance denial, tax pile, compliance review) feels like starting from zero. Nate argues this is the wrong standard. Every agent you build should make your next agent cheaper to build. If that isn't happening, you're collecting AI chores that will each rot on their own schedule, not building a compounding system.

The fix: one reusable rig — nine stages assembled once, pointed at any pile of sensitive, unstructured documents where a decision matters. Between builds, only the nouns change (context pack input and output template). Everything else transfers, and each component gets sharper with use.

---

## The Framework: [[reusable-agent-rig]]

A 9-stage architecture that transfers across document-heavy, high-stakes jobs:

1. **Ingestion** — turns messy docs into usable, source-linked text
2. **Normalization** — dates become dates, names become names (typed, clean data)
3. **Context Pack** — explicit scope decision: what the agent is and isn't allowed to read
4. **[Stages 4–8 per Substack; paywalled]** — execution, reasoning, and citation steps
5. **Receipt** — log of what the agent read, concluded, and flagged (the trust mechanism)
6. **The Hard Stop (Gate)** — the agent drafts only; never sends, files, submits, pays, or signs

**The flywheel:** each component sharpens with use. Build 3 costs a fraction of Build 1.

**Three build sequence:**
- **Build 1:** Email/calendar (training run — low stakes, builds the shelf)
- **Build 2:** Insurance Appeal Packet (Healthcare Claim Appeals Agent)
- **Build 3:** Tax-Year Packet (Tax Prep Organizer Agent)

**Two underlying Open Skills:**
- **Context Engineering** — scope and ingestion
- **Runbooks** — step-by-step execution logic

---

## How It Works (Three Builds, One Rig)

- **Build 1 (Email/Calendar):** Low stakes, familiar data. Tune the nine stages, document your primitives.
- **Build 2 (Insurance):** Same rig. Context pack = denial letter + policy docs. Output = cited appeal packet. Hard stop before filing. Leverages KFF data: <1% of denied claims get appealed; 33–50% of appeals win.
- **Build 3 (Tax):** Same rig. Context pack = year of financial docs. Output = cited packet for accountant review. Hard stop before submission.

## Where It Applies

Nate's test: "Anywhere life hands you sensitive documents, no structure, and a decision that matters."
- Insurance denials, tax prep, scheduling (the named examples)
- Vendor contract reviews, compliance gap analyses, benefits appeals, audit prep, grant applications
- Any domain where the other side has structure + automation, you have a pile, and a cited/reviewable draft is the right output

---

## Receipts

- **KFF (2024):** ~85 million denied in-network ACA marketplace claims; fewer than 1% appealed
- **Appeal win rate:** ~1/3 of internal denials reversed by insurer; ~half reversed by external reviewer; prior authorization: >80% reversal rate when challenged
- **2024 Senate Permanent Subcommittee on Investigations:** Largest Medicare Advantage insurers used algorithmic denial tools; UnitedHealthcare's denial rate more than doubled in two years
- **The asymmetry:** insurer side is automated + structured; consumer side has a pile — the rig closes that gap without changing the underlying rules

## The Contrarian Edge

Nate's implicit break from consensus: the dominant AI agent narrative is "build the first agent, ship it, be done." Nate's frame is that the FIRST agent's primary value is the reusable components it produces, not its direct output. The first agent is investment; the second and third are return. This reframes ROI from per-agent output to system compounding — a fundamentally different standard for what counts as a successful AI build.

---

## Mistake to Avoid

Building each agent as a standalone solution. Every agent built wrong is a maintenance chore forever. Every agent built right (with named, documented primitives) is a component reused indefinitely. The compounding gap between these two trajectories grows with every subsequent build.

---

## What It Means For You (Executive Actions)

1. **Audit current AI footprint** — for each agent, ask: what reusable components did this produce? If nothing transferred, you have chores not a system.
2. **Pick one high-stakes document pile** — apply the rig; build the context pack (scope) first; define the hard stop explicitly.
3. **Draw the hard stop before writing code** — what will the agent never do? Write it down. This is what enables high-stakes domains without enterprise legal friction.
4. **Measure flywheel progress** — track setup time across Build 1/2/3. If Build 3 doesn't cost less than Build 1, the components aren't truly reusable.
